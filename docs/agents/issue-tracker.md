# Issue Tracker

## Current Choice

Use local markdown issues until the repo has a confirmed remote issue tracker.

## Why

The project workspace was empty and not a Git repository during initial setup. Local markdown gives planning skills a safe place to draft and refine work without assuming GitHub, GitLab, Linear, Jira, or another tracker too early.

## Convention

- Put draft issues under `.scratch/issues/`.
- Use one markdown file per issue.
- Name files with a short, stable slug, for example `001-homepage-shell.md`.
- When the repo is connected to GitHub or another tracker, update this file and `AGENTS.md`.

## Issue Template

```markdown
# <Issue title>

## What to build

<One narrow vertical slice.>

## Acceptance criteria

- [ ] <Criterion>
- [ ] <Criterion>

## Blocked by

None.
```
